工具执行前的安全边界——PreToolUse 集中拦截与 safe/ask/allow-all

Lau · 2026-11-04 · 工作复盘 · 风越科技 Craft Agents 平台

Agent 平台里，工具执行如果没有统一的安全边界，每个工具都会长出自己的一套「能不能做」的判断，最终变成一盘散沙，而且很容易漏。我的做法是把它收敛成一条管线。

一、把会话与凭据放对位置

第一件事是 SessionToolContext：把会话信息和凭据注入到工具执行上下文。工具不再自己到处找「我是谁、我有哪些权限」，而是从统一上下文里取——权限判断因此有了一个稳定的输入。

二、PreToolUse：一道集中的闸门

第二件事是构建 PreToolUse 集中拦截管线：所有工具调用在真正执行之前，先过这一道闸门。它带来两个好处：

  • 集中硬拦截——不合规的调用在执行前就被拦下，而不是执行完再补救；
  • 人在回路回调——拿不准的动作，回调给人确认，而不是让 Agent 自己猜。

三、safe / ask / allow-all 三档

拦截不是二元的「放行 / 禁止」，而是三档：

  • safe——确定安全的操作，直接放行，不打断；
  • ask——有风险、可逆性不确定的操作，人在回路确认；
  • allow-all——明确禁止类操作，直接拦下。

这样新工具接入时自动继承这套边界，而不是每个工具各自实现一遍「安全检查」。

四、为什么是「集中」而不是「每个工具自己写」

安全边界分散到工具里，有三类必然失败：新工具会忘记写、写法不一致、改规则要改 N 处。集中拦截把「能不能做」从业务逻辑里抽出来，变成一个统一的、可测试的横切面。

五、复盘

权限不是给 Agent 上锁，而是给「不可靠的推理」加一道确定性的门。safe/ask/allow-all 的意义在于：把判断分成「确定安全」「需要人」「确定禁止」三类，各自用最合适的方式处理，而不是让模型替你做安全决策。
